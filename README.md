# WhatsApp Chat · GREEN-API

Минимальный React + TypeScript чат для **WhatsApp**. Исходное задание разрешает WhatsApp как альтернативу MAX; по запросу пользователя приложение переведено на WhatsApp.

## Запуск в VS Code

Node.js **22.12+** (проверено Node 24). Откройте корневую папку репозитория, где лежит `package.json`.

```bash
npm ci
npm run dev
```

Откройте URL из терминала, обычно http://127.0.0.1:5173. Оставьте терминал открытым. Для проверки без аккаунта нажмите **«Открыть демо без аккаунта»**. Демонстрационные ответы явно помечены, сеть не используется.

## Подключение WhatsApp

1. Выберите **WhatsApp-инстанс** GREEN-API.
2. Авторизуйте его в кабинете GREEN-API: на телефоне WhatsApp → Связанные устройства → Привязка устройства → QR-код из кабинета. Дождитесь состояния `authorized`.
3. Скопируйте `apiUrl`, `idInstance`, `apiTokenInstance` без изменения домена. Поддерживаются HTTPS `api.greenapi.com`, `api.green-api.com` и числовые кластеры, например `7107.api.greenapi.com`. Ссылка на страницу продукта не подходит. `/v3` для этой WhatsApp-версии не используется.
4. Для входящих сообщений в настройках инстанса оставьте `webhookUrl` пустым и включите `incomingWebhook`. Для статусов включите `outgoingWebhook`, для исходящих событий — `outgoingAPIMessageWebhook`/`outgoingMessageWebhook`; `stateWebhook` сообщает о состоянии аккаунта.
5. Введите параметры в приложении. Прочитайте предупреждение об очереди и подключитесь.
6. Создайте чат по международному номеру, например +998 90 123 45 67, и отправьте текст. Ответ собеседника должен появиться в открытом чате.

Используйте отдельный тестовый инстанс и одну вкладку-потребитель очереди. Приложение получает события через `receiveNotification`, затем подтверждает `deleteNotification`. Это **удаляет обработанное событие из очереди**; неподдерживаемые типы тоже подтверждаются, чтобы не блокировать очередь. Настройки приложения не меняют настройки аккаунта автоматически.

## Если соединение не устанавливается

- Запускайте проект через `npm run dev`, а не Live Server и не старый HTML-файл MAX
- Проверьте `apiUrl` именно этого инстанса и состояние `authorized`
- «Ошибка сети/браузера» не доказывает неверный токен: возможны недоступность сервера, CORS, блокировка сети или браузерного расширения. Приложение отдельно сообщает об истечении тайм-аута
- Если ошибка остаётся, сообщите текст ошибки и статус/тип запроса из DevTools; не отправляйте полный URL с токеном, сам токен или неотредактированный HAR
- При отсутствии ответов проверьте `incomingWebhook`, пустой `webhookUrl` и отсутствие другого потребителя очереди

## Реализация

- `App.tsx`: компактный вход, список чатов, переписка, ввод текста
- `greenApi.ts`: `getStateInstance`, `checkWhatsapp`, `sendMessage`, получение/подтверждение уведомлений
- `chatState.ts`: сообщения, непрочитанные, дедупликация, статусы
- `demo.ts`: изолированное демо без сети

Номера международные, включая +998. Текст до 20 000 символов. `checkWhatsapp` разрешает номер в WhatsApp ID; возвращённый `@lid` имеет приоритет, при старом формате ответа используется `номер@c.us`. Транспорт сопоставляет известные phone/LID идентификаторы входящих сообщений. Поддержаны Enter/Shift+Enter, черновики по чатам, отмена запросов при выходе и повтор polling с задержкой.

Удалены MAX-метод `checkAccount`, ограничения +7/+375, числовые MAX chatId, путь `/v3`, декоративный первый экран и необязательный поиск. Проверки безопасности, тесты, обработка повторов и отмена запросов сохранены.

Токены и чаты только в памяти. Нет localStorage, аналитики, внешних шрифтов или встроенных ключей. Токен виден владельцу браузера в DevTools, поскольку это клиентский прототип; для промышленного приложения нужен backend. После обновления страницы история очищается. Неопределённая отправка не повторяется автоматически, чтобы не отправить дубликат.
